## 🚨 The Problem

Modern Large Language Models (GPT-4, Gemini, Llama) are increasingly used by legal professionals for drafting complaints, applications, and court pleadings. But **LLMs hallucinate confidently** — and in legal contexts, this is catastrophic.

| LLM Failure Mode | Real-World Impact |
|---|---|
| **Fabricated Citations** — `(2023) 4 SCC 789` (doesn't exist) | Lawyer files a pleading citing a non-existent judgment. Court sanctions follow. |
| **Wrong Page Numbers** — `(2020) 5 SCC 12` instead of `(2020) 5 SCC 421` | Opposing counsel identifies the error. Credibility destroyed. |
| **Obsolete Statutes** — references `Section 420 IPC` instead of `Section 318 BNS` | Filed under repealed law. Application rejected on procedural grounds. |
| **Phantom Precedents** — fabricates entire case names with real-looking citations | Contempt of court proceedings. Disciplinary action by the Bar Council. |

> **In 2023, a U.S. federal court sanctioned attorneys for citing fabricated cases generated by ChatGPT.** This is not hypothetical — it is already happening in courts worldwide.

**Brahmo Citation Safety Engine ensures this never happens.**

## ⚡ Core Features

### 🔍 Citation Extraction Engine
Dynamically extracts Indian legal citations across **6 standard formats** using database-driven regex patterns:

| Format | Example | Jurisdiction |
|--------|---------|-------------|
| **SCC** | `(2024) 5 SCC 123` | Supreme Court of India |
| **SCC OnLine** | `2024 SCC OnLine Del 456` | Various High Courts |
| **AIR** | `AIR 2024 SC 123` | All India Reporter |
| **Cri LJ** | `2024 Cri LJ 789` | Criminal Law Journal |
| **SCR** | `(2024) 5 SCR 123` | Supreme Court Reports |
| **MANU** | `MANU/SC/0123/2024` | Manupatra Database |

- Patterns loaded dynamically from Supabase — **zero hardcoding**
- Falls back to comprehensive defaults if database is unavailable
- Deduplicates citations using canonical format normalization

---

### 🧪 Hallucination Detector (Pre-Filter)
Rule-based deterministic pre-filter that catches obviously impossible citations **before** wasting API calls:

| Rule | Detection | Severity |
|------|-----------|----------|
| **Future Year** | Citation year > 2026 | 🔴 ERROR — Auto-removed |
| **Impossible Volume** | SCC/SCR volume > 25 | 🔴 ERROR — Auto-removed |
| **Impossible Page** | Page number > 5000 | 🟡 WARNING — Flagged |
| **Pre-Modern Date** | Year < 1900 | 🟡 WARNING — Flagged |

```
Input:  (2028) 3 SCC 45
Result: ❌ REMOVED — "Citation year 2028 is in the future (> 2026). This case cannot exist."
```

---

### ✅ 3-Pass Citation Verifier
The core verification engine queries the **Indian Kanoon API** and uses a proprietary 3-pass validation algorithm to classify every citation:

```
Pass 1 — EXACT MATCH
  Scan ALL returned IK documents for the exact citation pattern
  in title + headline fields (with HTML stripping).
  Match found → ✅ VERIFIED

Pass 2 — CORRECTION DETECTION
  Scan ALL documents for same year/volume but different page number.
  Close match found → ⚠️ CORRECTED (with corrected citation)

Pass 3 — FABRICATION DETECTION
  No match found across any document →  ❌ REMOVED (Fabricated)
```

> **Why 3-Pass?** Indian Kanoon's `/search/` API is a general text search engine. Searching for a fabricated citation like `(2023) 4 SCC 789` will still return 10 results — they're just completely unrelated. A naive `docs.length > 0` check would mark every fabricated citation as VERIFIED. Our 3-pass architecture eliminates this false-positive vulnerability.

**Verified Live Results:**

| Citation | Status | Details |
|----------|--------|---------|
| `(1978) 1 SCC 240` | ✅ VERIFIED | Gudikanti Narasimhulu v. Public Prosecutor |
| `(2019) 9 SCC 1` | ✅ VERIFIED | Satish Ukey v. Devendra Fadnavis |
| `(2023) 4 SCC 789` | ❌ REMOVED | Fabricated — no IK match across all results |
| `(2020) 5 SCC 12` | ⚠️ CORRECTED | `→ (2020) 5 SCC 421` — page number mismatch |

### 📜 Section Normalizer (IPC → BNS)
India replaced three colonial-era criminal laws in July 2024:

| Old Law (Repealed) | New Law (Active) |
|---|---|
| Indian Penal Code (IPC) | Bharatiya Nyaya Sanhita (BNS) |
| Code of Criminal Procedure (CrPC) | Bharatiya Nagarik Suraksha Sanhita (BNSS) |
| Indian Evidence Act (IEA) | Bharatiya Sakshya Adhiniyam (BSA) |

LLMs still generate references to repealed sections. The normalizer dynamically converts them:

```
Input:  "offences under Sections 420, 406, 120B and 34 of the Indian Penal Code"
Output: "offences under Sections 318, 316, 61 and 3(5) BNS"
```

**Capabilities:**
- ✅ Bare references: `420 IPC` → `Section 318 BNS`
- ✅ Prefixed references: `Section 420 IPC`, `u/s 420 IPC`
- ✅ Compound lists: `Sections 420, 406 and 120B IPC`
- ✅ Case-insensitive: `120-b ipc`, `498-A IPC`
- ✅ Subsection support: `Section 156(3) CrPC` → `Section 175(3) BNSS`
- ✅ Obsolete year stripping: `Section 420 IPC, 1860` → `Section 318 BNS`
- ✅ 30+ mappings loaded from Supabase with fallback defaults

### 📊 Dynamic Verification Report
The pipeline compiles a real-time verification report with:

- **Safety Index** — Accuracy gauge (ring chart) dynamically computed from pipeline results
- **Total Entities** — Sum of verified citations + normalized sections
- **Verified Cases** — Citations confirmed via Indian Kanoon
- **Normalized Sections** — IPC/CrPC/IEA → BNS/BNSS/BSA conversions
- **Corrected Citations** — Page number / formatting fixes
- **Removed (Fabricated)** — Hallucinated citations caught and stripped
- **Unverified** — API failures / timeouts (honest uncertainty)
- **Kanoon API Calls** — Total API requests made
- **Pipeline Cost** — Estimated cost in INR

> All metrics are **backend-driven and dynamically derived** from actual pipeline operations. Zero hardcoded values.

## 🚀 Getting Started

### Prerequisites

- **Node.js** 18+ and **npm**
- **Indian Kanoon API Key** — [Request access](https://api.indiankanoon.org/)
- **Supabase Project** — [Create free project](https://supabase.com/)
- **LLM API Key(s)** — Google Gemini and/or Groq

### 1. Clone & Install

```bash
git clone https://github.com/your-username/brahmo-citation-safety.git
cd brahmo-citation-safety
npm install
```

### 2. Configure Environment

Create `.env.local` in the project root:

```env
# Indian Kanoon (Required for citation verification)
INDIAN_KANOON_API_KEY=your_api_key_here

# Supabase (Required for database-driven patterns & caching)
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_anon_key_here

# LLM Providers (comma-separated for key rotation)
GEMINI_API_KEY=key1,key2,key3
GROQ_API_KEY=key1,key2,key3
```

### 3. Run Development Server

```bash
npm run dev
```

Open [http://localhost:3000](http://localhost:3000) — the dashboard will be live.

### 4. Run Test Suite

```bash
# Offline deterministic pipeline tests
npx tsx src/lib/test_pipeline.ts

# Live Indian Kanoon API verification tests
npx tsx src/lib/test_verification_live.ts
```

### 5. Production Build

```bash
npm run build
npm start
```

### 6. Deploy to Vercel

```bash
npm i -g vercel
vercel --prod
```

> Add all environment variables in the Vercel dashboard under **Settings → Environment Variables**.

## 🔒 Engineering Principles

| Principle | Implementation |
|-----------|---------------|
| **Zero-Trust AI** | LLM output is treated as untrusted. Every citation is independently verified. |
| **Deterministic Correctness** | The safety pipeline uses zero AI — only regex, database lookups, and API verification. |
| **Auditability** | Every verification decision is traceable: citation → extraction → hallucination check → IK result → classification. |
| **Graceful Degradation** | If Supabase is down, the system uses hardened default patterns. If IK API times out, citations are marked UNVERIFIED (honest uncertainty), not silently passed. |
| **Multi-Key Resilience** | LLM generation rotates through multiple API keys with automatic failover across providers. |
| **Cache-First Architecture** | Verified citations are cached in Supabase with a 30-day TTL to minimize redundant API calls. |
| **Surprise-Test Hardened** | Regex patterns, normalization logic, and verification classification are designed to handle unseen legal queries and edge-case citation formats. |
